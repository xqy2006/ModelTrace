# GPT-6.1 Sol 实验样本（2026-10-02）

这批数据用于研究新模型的可分辨性，**未加入默认参考数据或指纹库**。在本批 Codex CLI 样本与 `d4131b3` 基线上，GPT-6.1 Sol 和 GPT-6 Astra 有明显重叠：加入候选后，新模型独立留出单回复命中 5/9、三回复组命中 1/3，而 Astra 的三回复交叉验证从 12/12 降至 9/12。当前结果不支持将本批数据直接启用为可靠的新类别。

## 文件与采样

- `enrollment.jsonl`：36 条可用录入回复，沿用 `challenge_suite.fingerprint_suite()` 的 36 题、12 个环境。
- `holdout.jsonl`：对 query-10..18 重新开会话取得的 9 条留出回复；未参与拟合。
- `failed-attempts.jsonl`：query-31 首次只返回 4 个数字的原始失败回复。原文保留，补采使用同题、同设置和新会话，没有补齐、裁剪或修复数字。
- `collection.json`：数据哈希、采样设置、首次可用率和证据限制。
- `validation.json`：上游原算法的基线／候选逐模型 CV 和逐条留出预测。
- `validate.py`：离线复现脚本，不调用模型、不访问网络、不改写默认库。

采样入口为官方 Codex CLI **0.159.1** 的现有 ChatGPT 登录，指定 `gpt-6.1-sol`、`model_reasoning_effort="low"`，每题一个独立的 `codex exec --ephemeral` 进程，最多同时 4 个。工具禁用；保存的事件中没有模型工具调用。原始用户题目和前缀按上游文本发送，原始最终回复保留在每条记录的 `text` 中，并带 SHA-256。

**这不是干净 API 请求的等价声明。** Codex 自身及主机指令仍然存在；挑战的 system 文本通过 `developer_instructions` 传入，该传输方式逐条标记。`model_id` 是请求的模型选择，CLI 没有独立返回可认证的服务模型版本，因此 `response_model` 为 null，`identity_independently_attested` 为 false。上下文 ID 以哈希记录，仅用于核对本批声明的唯一性。

首次可用率为录入 **35/36**、留出 **9/9**。一次输出过短的补采后，选用 36+9 条可用回复；兼容客户端合计 46 次逻辑 CLI 调用。另有一次较旧 CLI 0.153.4 的入口试采被服务端拒绝，没有模型回复，不计入这些数值样本。CLI 内部的网络重连事件逐条记录；逻辑调用次数不等于独立观察到的后端生成尝试次数。

45 条选用回复中，**33 条恰好符合请求数量，12 条数量不完全相同**，都保留原文。36 条录入均满足上游原有严格长度门槛。跨回复发现 2 个共享的 12 数连续片段；此筛查只是诊断，不能证明或否定独立生成。没有根据评分结果重采或筛选回复。

## 原算法结果

基线：ModelTrace `d4131b30243dfa05e70180b5eedde742103f1d73`，17 个模型／612 条回复；实验候选为 18 个模型／648 条回复。数值算法、题目、权重均未改动。

| 检查 | GPT-6.1 Sol |
| --- | --- |
| 单回复交叉验证 | 20/36 |
| 双回复交叉验证 | 24/36 |
| 三回复交叉验证 | 6/12 |
| 独立留出单回复 top-1 | 5/9 |
| 独立留出三回复组 top-1 | 1/3 |

| 原有模型退步 | 基线 → 候选 |
| --- | --- |
| GPT-6 Astra，单回复 CV | 35/36 → 25/36 |
| GPT-6 Astra，双回复 CV | 36/36 → 25/36 |
| GPT-6 Astra，三回复 CV | 12/12 → 9/12 |
| GPT-5.6 Sol，单回复 CV | 35/36 → 34/36 |
| GPT-6 Sol，单回复 CV | 33/36 → 32/36 |
| Claude Opus 4.8，双回复 CV | 36/36 → 35/36 |

留出数据的中文 prose 和英文 prose 三回复组仍归到 Astra，英文 JSON 三回复组归到 GPT-6.1 Sol。这些计数描述当前采样入口和固定题目的表现，不能推广为所有入口的识别准确率，也不能用于判断供应商身份。

## 复现

使用仓库已有的 Python／NumPy 环境，从仓库根目录运行：

```sh
python3 data/research/gpt-6.1-sol-2026-10-02/validate.py
```

脚本校验原始回复哈希、完整题目覆盖、请求文本、留出隔离和失败／补采关联，随后在内存中重建候选并重新计算逐模型 CV 与留出预测，最后确认默认参考文件和核心源文件未变。源码／基线数据哈希被固定到上述提交；若基线已变化，脚本会明确失败，需要回到该基线复现，不能自动改写记录。

这些文件供后续研究或方法改进使用。激活前应重新验证新模型可分辨性与原有模型回归，不能只检查总命中率。
